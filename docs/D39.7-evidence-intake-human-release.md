## State machine: don't conflate fact, review and deployment
1. **RECEIVED:** evidence file/link actually present with timestamp, collector and service ID.
2. **TRIAGED:** source/rights, data quality and conflicts documented. Missing/unsafe evidence → **RETURN_FOR_EVIDENCE** without changing public records.
3. **QA_READY:** all applicable F1–F4 gates pass and a reviewer who did not collect it validates. Reviewer can choose **PASS**, **FAIL** or **NEEDS_EVIDENCE**; a PASS is *not* publication approval.
4. **FOUNDER_DECISION:** Founder chooses one explicit scope:
   - `APPROVE_ADDRESS_ONLY` — safe institution/address copy; no service-open guarantee, no visitor navigation.
   - `APPROVE_SERVICE_NO_ROUTE` — unit-specific operational service and hours copy, no visitor entrance navigation.
   - `APPROVE_ENTRANCE_ROUTE` — exact reviewed entrance/vehicle bay coordinate, navigation link and access copy after F1–F6, real-device route and QA.
   - `DEFER` / `REJECT` — no promotion; record specific reason.
5. **DEPLOYED:** separate maintainer commits only authorized fields, tests live mobile/desktop, captures release SHA, rollback and monitoring. Approval and deployment are separate events.
6. **REVERIFY/REVOKE:** expiry, conflicting new official notices, moved vehicle, changed gate or failed user arrival → suspend link and reopen validation.

The state **HOLD_PENDING_EVIDENCE** is a current protective workflow status, **not** a recorded Founder decision.
